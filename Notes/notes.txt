- Challenge 2: Run again strace and you get
""" 
	rt_sigaction(SIGALRM, {sa_handler=0x558b6b10a350, sa_mask=[ALRM], sa_flags=SA_RESTORER|SA_RESTART, sa_restorer=0x7f29a7a0e5d0}, {sa_handler=SIG_DFL, sa_mask=[], sa_flags=0}, 8) = 0
	rt_sigaction(SIGCONT, {sa_handler=0x558b6b10a350, sa_mask=[CONT], sa_flags=SA_RESTORER|SA_RESTART, sa_restorer=0x7f29a7a0e5d0}, {sa_handler=SIG_DFL, sa_mask=[], sa_flags=0}, 8) = 0
	alarm(10)                               = 0
	pause()                                 = ? ERESTARTNOHAND (To be restarted if no handler)
	--- SIGALRM {si_signo=SIGALRM, si_code=SI_KERNEL} ---
	rt_sigreturn({mask=[]})                 = -1 EINTR (Interrupted system call)
	write(2, "\33[31mYou were eaten by a grue. F"..., 40You were eaten by a grue. FAIL
	) = 40
"""
SIGALRM: This specifies the signal being handled here. SIGALRM is a signal sent to a process after a timer set by alarm() expires. It's often used to implement timeouts.
SIGCONT: This signal is sent to a process to resume it after it has been stopped (using SIGSTOP or SIGTSTP). The same signal handler and flags are applied to this signal as for SIGALRM.

We run ./riddle and in another terminal we run ./challenge_2_script.sh

The alarm(10) means that the SIGALRM signal will be invoked during the pause after 10 seconds. In order to prevent that, we need to send in those 10 seconds an SIGCONT signal in 
order for the process to resume. Firstly, we need to find the pid of the riddle process with the command "ps aux | grep riddle". Then we need to send the signal to that process 
with the kill command (kill -SIGCONT <pid>). We put all of that in a script we called challenge_2_script.sh.

grep '[r]iddle': Searches the output of ps aux for processes that match the string riddle. The brackets [] are used to prevent grep from matching its own process in the results.
Normally, running grep riddle would also return the grep riddle command itself as a match, but [r]iddle makes sure only processes containing "riddle" are matched.

[ -n "$pid" ]: This condition checks if the variable pid is non-empty, which means the "riddle" process was found. The -n flag checks if the string (PID in this case) is not null.

Or another option is to run the ./challenge_2_script_version_2.sh script where we run the ./riddle on the background, get the pid and send the SIGCONT signal.
